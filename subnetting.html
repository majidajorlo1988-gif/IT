Subnetting چیست؟

Subnetting یا تقسیم‌بندی شبکه، یکی از مهم‌ترین مفاهیم در طراحی شبکه‌های IP است. در Subnetting یک Network بزرگ‌تر را به چند Network کوچک‌تر تقسیم می‌کنیم تا مدیریت، امنیت، Routing و استفاده از آدرس‌های IP بهتر انجام شود.

فرض کنید یک سازمان شبکه 192.168.10.0/24 دارد. اگر همه کاربران، سرورها، دوربین‌ها و تجهیزات مدیریتی در یک Subnet قرار بگیرند، شبکه به‌مرور بزرگ و مدیریت آن دشوار می‌شود.

با Subnetting می‌توان همین Network را به چند بخش منطقی تقسیم کرد؛ مثلاً یک Subnet برای کاربران، یک Subnet برای CCTV، یک Subnet برای Serverها و یک Subnet برای Management.

نکته مهم: Subnetting فقط یک محاسبه ریاضی نیست؛ در شبکه‌های واقعی، یکی از پایه‌های طراحی صحیح IP Addressing و Routing محسوب می‌شود.

IPv4 چگونه ساخته شده است؟

یک IPv4 Address دارای 32 بیت است که به چهار Octet تقسیم می‌شود. هر Octet می‌تواند عددی بین 0 تا 255 داشته باشد.

IPv4 = 32 bits = 4 × 8 bits

برای مثال:

192.168.10.25

در یک Subnet مشخص، بخشی از این 32 بیت برای مشخص کردن Network و بخش دیگر برای مشخص کردن Host استفاده می‌شود.

Network ID و Host ID

IP Address
←
Network Portion
+
Host Portion

فرض کنیم آدرس زیر را داریم:

192.168.10.25/24

در Prefix Length برابر با /24، تعداد 24 بیت برای Network و 8 بیت برای Host استفاده می‌شود.

بنابراین:

مورد مقدار
IP Address 192.168.10.25
Prefix /24
Subnet Mask 255.255.255.0
Network Address 192.168.10.0
Broadcast Address 192.168.10.255
Usable Host Range 192.168.10.1 – 192.168.10.254

Subnet Mask چیست؟

Subnet Mask مشخص می‌کند کدام قسمت از IP مربوط به Network و کدام قسمت مربوط به Host است.

برای مثال:

IP Address : 192.168.10.25 Subnet Mask: 255.255.255.0 CIDR : /24

مقدار /24 یعنی 24 بیت اول مربوط به Network هستند.

CIDR چیست؟

CIDR مخفف Classless Inter-Domain Routing است. در CIDR به‌جای استفاده صرف از کلاس‌های قدیمی A، B و C، تعداد بیت‌های Network را با Prefix Length مشخص می‌کنیم.

/24 255.255.255.0
/25 255.255.255.128
/26 255.255.255.192
/27 255.255.255.224
/28 255.255.255.240
/29 255.255.255.248

چطور تعداد Hostها را محاسبه کنیم؟

اگر تعداد بیت‌های Host را بدانیم، می‌توانیم تعداد Addressهای موجود در Subnet را محاسبه کنیم.

Total Addresses = 2^h

در بیشتر Subnetهای IPv4 معمولی، Network Address و Broadcast Address قابل تخصیص به Host نیستند.

Usable Hosts = 2^h - 2

البته /31 برای لینک‌های Point-to-Point و /32 برای Host Route استثناهای مهمی هستند.

جدول مهم Subnetها

CIDR Subnet Mask Total IP Usable Host Block Size
/24 255.255.255.0 256 254 256
/25 255.255.255.128 128 126 128
/26 255.255.255.192 64 62 64
/27 255.255.255.224 32 30 32
/28 255.255.255.240 16 14 16
/29 255.255.255.248 8 6 8
/30 255.255.255.252 4 2 4

مثال عملی: تقسیم 192.168.10.0/24

فرض کنیم یک شبکه با آدرس زیر داریم:

192.168.10.0/24

این شبکه 256 Address دارد و در حالت معمول 254 Host قابل استفاده در اختیار ما قرار می‌دهد.

اگر بخواهیم آن را به چهار Subnet مساوی تقسیم کنیم، Prefix را از /24 به /26 تغییر می‌دهیم.

چرا /26؟
چون با اضافه کردن 2 بیت به بخش Network، چهار Subnet ایجاد می‌شود:
2² = 4

Subnet شماره 1

Network : 192.168.10.0/26 Usable : 192.168.10.1 - 192.168.10.62 Broadcast : 192.168.10.63

Subnet شماره 2

Network : 192.168.10.64/26 Usable : 192.168.10.65 - 192.168.10.126 Broadcast : 192.168.10.127

Subnet شماره 3

Network : 192.168.10.128/26 Usable : 192.168.10.129 - 192.168.10.190 Broadcast : 192.168.10.191

Subnet شماره 4

Network : 192.168.10.192/26 Usable : 192.168.10.193 - 192.168.10.254 Broadcast : 192.168.10.255
نتیجه:
یک /24 را به چهار /26 تقسیم کردیم و هر Subnet دارای 62 Host قابل استفاده شد.

تقسیم /24 به /25، /26 و /27

با تغییر Prefix Length، اندازه Subnet نیز تغییر می‌کند.

Prefix Subnetها در 192.168.10.0/24 Host قابل استفاده
/25 .0 و .128 126
/26 .0، .64، .128، .192 62
/27 .0، .32، .64، .96، .128، .160، .192، .224 30

VLSM چیست؟

VLSM یا Variable Length Subnet Mask به ما اجازه می‌دهد Subnetهایی با اندازه‌های متفاوت ایجاد کنیم.

این روش در شبکه‌های واقعی بسیار کاربردی است؛ چون همه بخش‌های سازمان به تعداد یکسانی IP نیاز ندارند.

سناریوی یک شبکه سازمانی

فرض کنیم شبکه اصلی ما:

192.168.10.0/24

نیازهای سازمان:

  • کاربران: حدود 50 دستگاه
  • CCTV: حدود 25 دوربین و تجهیزات مرتبط
  • Serverها: حدود 10 دستگاه
  • Management: حدود 5 دستگاه
  • Point-to-Point: دو IP

Subnet کاربران

192.168.10.0/26 Network : 192.168.10.0 Usable : 192.168.10.1 - 192.168.10.62 Broadcast : 192.168.10.63 Hosts : 62

Subnet دوربین‌ها

192.168.10.64/27 Network : 192.168.10.64 Usable : 192.168.10.65 - 192.168.10.94 Broadcast : 192.168.10.95 Hosts : 30

Subnet سرورها

192.168.10.96/28 Network : 192.168.10.96 Usable : 192.168.10.97 - 192.168.10.110 Broadcast : 192.168.10.111 Hosts : 14

Subnet Management

192.168.10.112/29 Network : 192.168.10.112 Usable : 192.168.10.113 - 192.168.10.118 Broadcast : 192.168.10.119 Hosts : 6

Point-to-Point Link

192.168.10.120/30 Network : 192.168.10.120 Usable : 192.168.10.121 - 192.168.10.122 Broadcast : 192.168.10.123 Hosts : 2
مزیت VLSM:
به‌جای اینکه برای همه واحدها یک /24 یا حتی /26 اختصاص دهیم، برای هر بخش دقیقاً متناسب با نیاز آن Subnet طراحی می‌کنیم. در نتیجه IP Addressها بهتر استفاده می‌شوند و فضای کافی برای توسعه آینده باقی می‌ماند.

Subnet و VLAN چه تفاوتی دارند؟

این دو مفهوم بسیار به هم مرتبط هستند اما یکی نیستند.

VLAN Subnet
مفهوم Layer 2 مفهوم Layer 3
Broadcast Domain را جدا می‌کند IP Network را تعریف می‌کند
روی Switch بسیار مهم است در Routing و IP Addressing بسیار مهم است
مثلاً VLAN 20 مثلاً 192.168.20.0/24

در بسیاری از طراحی‌های سازمانی، هر VLAN یک Subnet اختصاصی دارد. مثلاً:

VLAN 10 → Users → 192.168.10.0/24 VLAN 20 → CCTV → 192.168.20.0/24 VLAN 30 → Servers → 192.168.30.0/24 VLAN 40 → Management → 192.168.40.0/24

چرا Subnetting در شبکه‌های سازمانی مهم است؟

  • کاهش Broadcast Domain
  • بهبود ساختار IP Addressing
  • مدیریت بهتر VLANها
  • کنترل بهتر ترافیک بین بخش‌های مختلف
  • امکان اعمال Policyهای Firewall و ACL
  • بهبود Troubleshooting
  • استفاده بهینه‌تر از IP Addressها
  • امکان طراحی شبکه برای رشد آینده

یک مثال واقعی از طراحی شبکه

فرض کنید در یک سازمان چند بخش مختلف داریم. کاربران نباید مستقیماً به شبکه دوربین‌ها دسترسی داشته باشند و تجهیزات مدیریتی نیز باید از شبکه کاربران جدا باشند.

نمونه طراحی

VLAN 10 Users 192.168.10.0/24 VLAN 20 CCTV 192.168.20.0/24 VLAN 30 Servers 192.168.30.0/24 VLAN 40 Management 192.168.40.0/24

سپس روی Router یا Layer 3 Switch می‌توان Routing بین VLANها را کنترل کرد و با ACL یا Firewall مشخص کرد کدام بخش اجازه دسترسی به بخش دیگر را دارد.

دستورهای کاربردی Cisco

برای بررسی وضعیت Interfaceها و IP Addressها در تجهیزات Cisco:

show ip interface brief

برای مشاهده تنظیمات یک Interface:

show running-config interface GigabitEthernet0/1

و برای مشاهده Routing Table:

show ip route

در زمان Troubleshooting، ترکیب اطلاعات IP Address، Subnet Mask، VLAN و Routing Table معمولاً تصویر بسیار خوبی از وضعیت شبکه به ما می‌دهد.

Wildcard Mask چیست؟

Wildcard Mask در برخی تنظیمات شبکه، مخصوصاً ACL و OSPF، کاربرد دارد. در ساده‌ترین حالت، Wildcard Mask مکمل Subnet Mask نسبت به 255.255.255.255 است.

Subnet Mask : 255.255.255.0 Wildcard : 0.0.0.255

برای مثال، برای یک /24، Wildcard Mask برابر با 0.0.0.255 است.

اشتباهات رایج در Subnetting

  • انتخاب Subnet کوچک‌تر از نیاز واقعی شبکه
  • فراموش کردن Network Address و Broadcast Address
  • استفاده از IPهای یکسان در دو Subnet
  • ایجاد Subnetهای Overlap
  • اشتباه در محاسبه Block Size
  • عدم در نظر گرفتن رشد آینده سازمان
  • تصور اینکه VLAN و Subnet دقیقاً یک مفهوم هستند
  • تنظیم اشتباه Default Gateway
یک نکته مهم در طراحی:
فقط بر اساس تعداد فعلی دستگاه‌ها Subnet طراحی نکنید. اگر یک بخش امروز 40 دستگاه دارد، ممکن است چند ماه بعد به 70 یا 100 دستگاه برسد. همیشه ظرفیت توسعه را نیز در نظر بگیرید.

روش سریع محاسبه Subnet

برای حل سریع مسائل Subnetting می‌توان این مراحل را دنبال کرد:

  1. Prefix Length را مشخص کنید.
  2. تعداد بیت‌های Host را محاسبه کنید.
  3. تعداد کل Addressها را به دست آورید.
  4. Block Size را مشخص کنید.
  5. Network Address را پیدا کنید.
  6. Broadcast Address را پیدا کنید.
  7. محدوده Usable Hostها را مشخص کنید.
مثال سریع:
برای 192.168.10.70/26:

Block Size = 64
Subnetها = .0، .64، .128، .192
بنابراین IP شماره 70 داخل Subnet دوم قرار دارد:
Network = 192.168.10.64
Broadcast = 192.168.10.127
Usable = 192.168.10.65 تا 192.168.10.126

جمع‌بندی

Subnetting یکی از پایه‌ای‌ترین مهارت‌های Networking است و تقریباً در تمام طراحی‌های حرفه‌ای شبکه با آن سروکار داریم.

وقتی مفهوم‌های Network ID، Host ID، Subnet Mask، CIDR، Network Address و Broadcast Address را به‌خوبی درک کنیم، طراحی IP Addressing بسیار ساده‌تر می‌شود.

در شبکه‌های سازمانی، Subnetting معمولاً در کنار VLAN، Routing، ACL و Firewall استفاده می‌شود تا شبکه‌ای ساختاریافته، قابل مدیریت و قابل توسعه ایجاد شود.

خلاصه حرفه‌ای:
IP Addressing خوب فقط به معنی «IP دادن به دستگاه‌ها» نیست؛ یک طراحی صحیح باید از ابتدا مشخص کند هر بخش شبکه چه محدوده‌ای دارد، چه تعداد Host نیاز دارد، چقدر ظرفیت رشد دارد و چگونه با VLAN و Routing با سایر بخش‌ها ارتباط برقرار می‌کند.
