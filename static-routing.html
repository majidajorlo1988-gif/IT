Static Routing چیست؟

Static Routing روشی برای مسیریابی است که در آن مسیر رسیدن به یک شبکه مقصد به‌صورت دستی روی Router یا Layer 3 Device تعریف می‌شود.

برخلاف Dynamic Routing Protocolها، در Static Routing دستگاه خودش مسیر جدیدی را از طریق پروتکل‌هایی مثل OSPF یا EIGRP یاد نمی‌گیرد؛ مسیر توسط Administrator مشخص می‌شود.

تعریف ساده:
در Static Routing به Router می‌گوییم: «اگر Packet مقصدش این Network بود، آن را از این مسیر یا Next-Hop ارسال کن.»

Routing Table چیست؟

Router برای تصمیم‌گیری درباره Forward کردن Packet از Routing Table استفاده می‌کند.

Routing Table شامل اطلاعاتی درباره Networkهای مقصد و مسیر رسیدن به آن‌ها است. Static Route یکی از منابعی است که می‌تواند یک Entry در Routing Table ایجاد کند.

یک سناریوی ساده

فرض کنید دو Router داریم.

Router R1

LAN: 192.168.10.0/24 WAN: 10.0.0.1/30

Router R2

WAN: 10.0.0.2/30 LAN: 192.168.20.0/24

R1 شبکه 192.168.20.0/24 را به‌صورت مستقیم نمی‌شناسد. بنابراین باید به R1 بگوییم برای رسیدن به این شبکه، Packet را به R2 ارسال کند.

R1(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.2

اکنون R1 می‌داند که برای رسیدن به 192.168.20.0/24 باید Next-Hop برابر با 10.0.0.2 باشد.

ساختار دستور ip route در Cisco

در Cisco IOS، ساختار پایه Static Route به شکل زیر است:

ip route destination-network subnet-mask next-hop

بنابراین:

ip route 192.168.20.0 255.255.255.0 10.0.0.2
قسمت مقدار معنی
Destination 192.168.20.0 شبکه مقصد
Mask 255.255.255.0 Subnet Mask مقصد
Next-Hop 10.0.0.2 Router بعدی

Next-Hop چیست؟

Next-Hop آدرس IP دستگاهی است که Router فعلی باید Packet را برای ادامه مسیر به آن تحویل دهد.

در سناریوی بالا:

R1 10.0.0.1
Next-Hop 10.0.0.2
Destination 192.168.20.0/24

بنابراین Packet ابتدا از R1 به R2 منتقل می‌شود و سپس R2 آن را به سمت شبکه مقصد Forward می‌کند.

Static Route با Interface

Static Route را می‌توان با Interface خروجی نیز تعریف کرد. Syntax دقیق بسته به نوع Interface و پلتفرم متفاوت است، بنابراین در شبکه‌های Ethernet معمولاً استفاده از Next-Hop صریح انتخاب قابل‌فهم‌تری است.

ip route 192.168.20.0 255.255.255.0 GigabitEthernet0/0
نکته:
قبل از استفاده از Exit Interface باید رفتار Forwarding و نوع Interface را در پلتفرم موردنظر بررسی کرد. برای طراحی‌های Ethernet معمولاً مشخص کردن Next-Hop می‌تواند ابهام کمتری داشته باشد.

Default Route چیست؟

Default Route زمانی استفاده می‌شود که Router برای مقصد موردنظر Route دقیق‌تری در Routing Table نداشته باشد.

رایج‌ترین Default Route در IPv4:

ip route 0.0.0.0 0.0.0.0 10.0.0.2

این Route به زبان ساده یعنی:

اگر برای مقصد Packet مسیر مشخص‌تری نداری، آن را به 10.0.0.2 بفرست.

Default Route در شبکه‌هایی که یک مسیر اصلی به Internet یا Upstream Router دارند بسیار رایج است.

Cisco نیز Static Route را مسیر ثابتی می‌داند که به‌صورت دستی تعریف می‌شود و در صورت تغییر Topology، Administrator باید مسیر را به‌روزرسانی کند. :contentReference[oaicite:1]{index=1}

چه زمانی Static Routing انتخاب خوبی است؟

  • شبکه‌های کوچک و ساده
  • Branchهای کوچک
  • شبکه‌هایی با یک مسیر مشخص به Upstream
  • Default Route به سمت Internet
  • شبکه‌های آزمایشگاهی و Lab
  • مسیرهای خاص و محدود
  • برخی سناریوهای Backup و Failover
  • Routeهای مدیریتی یا خاص که نمی‌خواهیم توسط پروتکل Dynamic منتشر شوند

Floating Static Route چیست؟

Floating Static Route نوعی Static Route پشتیبان است که با Administrative Distance بالاتر تنظیم می‌شود تا Route اصلی در شرایط عادی ترجیح داده شود.

مثلاً فرض کنید یک مسیر اصلی و یک مسیر Backup داریم.

! Primary Route ip route 192.168.50.0 255.255.255.0 10.0.0.2 ! Backup Route ip route 192.168.50.0 255.255.255.0 20.0.0.2 200

در این مثال Route دوم Administrative Distance بالاتری دارد، بنابراین در شرایط عادی Route اصلی ترجیح داده می‌شود.

کاربرد واقعی:
می‌توان از این تکنیک برای ایجاد یک مسیر Backup در کنار لینک اصلی استفاده کرد؛ البته برای Failover واقعی باید وضعیت لینک، Reachability و مکانیزم‌های Tracking نیز درست طراحی شوند.

Administrative Distance چیست؟

وقتی Router چند مسیر برای رسیدن به یک مقصد داشته باشد، Administrative Distance یکی از معیارهایی است که برای انتخاب منبع Route استفاده می‌شود.

در Cisco، مقدار کمتر معمولاً ترجیح داده می‌شود.

Route Source نمونه AD
Connected 0
Static 1
OSPF 110
RIP 120

مقادیر بالا نمونه‌های رایج Cisco IOS هستند و می‌توانند بسته به Platform یا تنظیمات تغییر کنند. برای Floating Static Route معمولاً AD را بالاتر از مسیر اصلی قرار می‌دهیم.

Static Routing بین دو شعبه

یکی از سناریوهای جالب در شبکه‌های سازمانی، ارتباط دو Branch با یک لینک WAN است.

Branch A

LAN 192.168.10.0/24 WAN 10.10.10.1/30

Branch B

LAN 192.168.20.0/24 WAN 10.10.10.2/30

روی Branch A:

ip route 192.168.20.0 255.255.255.0 10.10.10.2

و روی Branch B:

ip route 192.168.10.0 255.255.255.0 10.10.10.1

حالا هر دو Router مسیر شبکه LAN طرف مقابل را می‌شناسند.

بررسی Static Route در Cisco

بعد از تنظیم Route، یکی از مهم‌ترین دستورها برای بررسی Routing Table این است:

show ip route

Static Routeها در خروجی Routing Table با حرف S نمایش داده می‌شوند. :contentReference[oaicite:2]{index=2}

برای بررسی دقیق‌تر یک مقصد نیز می‌توان از:

show ip route 192.168.20.0

استفاده کرد.

بررسی Interfaceها

قبل از اینکه سراغ Routing برویم، بهتر است مطمئن شویم Interfaceها Up هستند و IP صحیح دارند.

show ip interface brief

همچنین:

show running-config interface GigabitEthernet0/0

تست ارتباط

بعد از تنظیم Route می‌توانیم با Ping ارتباط را بررسی کنیم:

ping 192.168.20.1

و برای بررسی مسیر:

traceroute 192.168.20.1

اگر Ping موفق نبود، نباید فوراً نتیجه بگیریم که Static Route اشتباه است. باید کل مسیر را بررسی کنیم.

چک‌لیست Troubleshooting

  1. IP Address و Subnet Mask را بررسی کنید.
  2. Interfaceهای مربوطه را بررسی کنید.
  3. Next-Hop را Ping کنید.
  4. Routing Table را بررسی کنید.
  5. وجود Route مقصد را بررسی کنید.
  6. Return Route را بررسی کنید.
  7. Default Gateway را بررسی کنید.
  8. ACL و Firewall را بررسی کنید.
  9. در صورت وجود NAT، Translation را بررسی کنید.
  10. با Traceroute محل توقف Packet را پیدا کنید.

حذف Static Route

برای حذف یک Static Route در Cisco معمولاً همان دستور را با no اجرا می‌کنیم.

no ip route 192.168.20.0 255.255.255.0 10.0.0.2

ذخیره Configuration

بعد از انجام تغییرات، بسته به پلتفرم Cisco و روش مدیریت دستگاه، Configuration را در Startup Configuration ذخیره کنید تا بعد از Reload از بین نرود.

copy running-config startup-config

Static Routing در شبکه واقعی

Static Routing هنوز هم در شبکه‌های حرفه‌ای جایگاه خودش را دارد. قرار نیست همیشه برای Routing از یک پروتکل Dynamic استفاده کنیم.

در یک شبکه واقعی ممکن است هم‌زمان داشته باشیم:

  • Connected Routes
  • Static Routes
  • Default Route
  • OSPF یا سایر Dynamic Routing Protocolها
  • Routeهای Backup

انتخاب روش مناسب به اندازه شبکه، تعداد مسیرها، نیاز به Failover، پیچیدگی Topology و نیازهای عملیاتی سازمان بستگی دارد.

جمع‌بندی حرفه‌ای:
Static Routing ساده به نظر می‌رسد، اما در Troubleshooting شبکه یکی از مفاهیم بسیار مهم است. اگر بدانیم Router چگونه مقصد را از Routing Table پیدا می‌کند و Next-Hop چگونه انتخاب می‌شود، بسیاری از مشکلات ارتباط بین Subnetها و Branchها سریع‌تر قابل تشخیص خواهند بود.
