SWITCHING

STP و RSTP چیست؟ راهنمای جلوگیری از Loop در شبکه

Spanning Tree Protocol یکی از مهم‌ترین مکانیزم‌های شبکه‌های Ethernet برای جلوگیری از ایجاد Loop در لایه دوم است. در این مقاله با STP، RSTP، Root Bridge، BPDU، Port Stateها، PortFast و BPDU Guard آشنا می‌شویم.

Switching Intermediate 12 دقیقه مطالعه

STP چیست؟

STP مخفف Spanning Tree Protocol است. این پروتکل برای جلوگیری از Loop در شبکه‌های لایه دوم Ethernet طراحی شده است.

در شبکه‌های سازمانی معمولاً برای افزایش Redundancy بین سوئیچ‌ها چند مسیر فیزیکی ایجاد می‌شود. این کار برای High Availability مفید است، اما اگر کنترل نشود می‌تواند باعث ایجاد Loop شود.

هدف اصلی STP: جلوگیری از Loop در Layer 2 در حالی که مسیرهای Redundant در شبکه حفظ می‌شوند.

چرا Loop در شبکه خطرناک است؟

برخلاف برخی پروتکل‌های لایه سوم، فریم‌های Ethernet مکانیزم TTL مشابه IP ندارند. بنابراین در صورت ایجاد Loop، یک فریم ممکن است بارها در شبکه گردش کند.

این اتفاق می‌تواند باعث افزایش شدید ترافیک و ایجاد Broadcast Storm شود.

یک مثال ساده

Switch A
↔
Switch B
↔
Switch C
↔
Switch A

این ساختار یک مسیر حلقه‌ای ایجاد کرده است. STP با قرار دادن برخی لینک‌ها در وضعیت Blocking/Discarding، مسیر Loop را می‌شکند.

Broadcast Storm چیست؟

Broadcast زمانی اتفاق می‌افتد که یک فریم برای تمام دستگاه‌های موجود در Broadcast Domain ارسال شود.

اگر این فریم وارد یک Loop لایه دوم شود، می‌تواند بارها در شبکه تکرار شود. نتیجه می‌تواند مصرف شدید پهنای باند، افزایش CPU سوئیچ‌ها، Packet Loss و حتی از دسترس خارج شدن شبکه باشد.

نکته مهم: یک Loop ساده بین دو یا چند سوئیچ می‌تواند در مدت کوتاهی عملکرد کل شبکه را مختل کند.

STP چگونه Loop را از بین می‌برد؟

STP توپولوژی شبکه را بررسی می‌کند و از بین مسیرهای موجود، یک ساختار منطقی بدون Loop ایجاد می‌کند.

برای این کار یکی از سوئیچ‌ها به عنوان Root Bridge انتخاب می‌شود و سپس بهترین مسیرها نسبت به Root تعیین می‌شوند.

Root Bridge چیست؟

Root Bridge نقطه مرجع محاسبات STP است. سایر سوئیچ‌ها بهترین مسیر خود را نسبت به Root Bridge محاسبه می‌کنند.

انتخاب Root Bridge بر اساس Bridge ID انجام می‌شود. Bridge ID شامل Priority و MAC Address است.

قاعده مهم: در فرآیند انتخاب Root Bridge، Bridge ID پایین‌تر برنده می‌شود.

Root Port چیست؟

در هر Non-Root Switch، پورتی که بهترین مسیر به سمت Root Bridge را فراهم می‌کند، Root Port نام دارد.

هر سوئیچ Non-Root معمولاً یک Root Port دارد.

Designated Port چیست؟

Designated Port پورتی است که برای یک Segment به عنوان مسیر Forwarding انتخاب می‌شود.

در یک طراحی STP، ترکیب Root Port و Designated Port باعث می‌شود توپولوژی نهایی بدون Loop باقی بماند.

BPDU چیست؟

BPDU مخفف Bridge Protocol Data Unit است.

سوئیچ‌های دارای STP از BPDU برای تبادل اطلاعات مربوط به Spanning Tree و محاسبه توپولوژی استفاده می‌کنند.

به زبان ساده: سوئیچ‌ها با استفاده از BPDU درباره ساختار STP با یکدیگر اطلاعات ردوبدل می‌کنند.

STP Port Stateها

در STP کلاسیک، پورت‌ها می‌توانند مراحل مختلفی را طی کنند تا وضعیت نهایی آن‌ها مشخص شود.

State کاربرد
Blocking جلوگیری از Forward کردن فریم‌ها برای جلوگیری از Loop
Listening بررسی توپولوژی و BPDUها
Learning یادگیری MAC Addressها بدون Forward معمول ترافیک
Forwarding ارسال و دریافت عادی فریم‌ها
Disabled پورت در فرآیند STP فعال نیست

RSTP چیست؟

RSTP مخفف Rapid Spanning Tree Protocol است و نسخه سریع‌تر و بهینه‌تر STP محسوب می‌شود.

هدف اصلی RSTP کاهش زمان Convergence در هنگام تغییرات توپولوژی است.

ویژگی STP RSTP
استاندارد 802.1D 802.1w
Convergence کندتر سریع‌تر
Port Roles Root / Designated Root / Designated / Alternate / Backup
کاربرد شبکه‌های قدیمی‌تر شبکه‌های مدرن

Convergence چیست؟

زمانی که توپولوژی شبکه تغییر می‌کند، مثلاً یک لینک قطع می‌شود، سوئیچ‌ها باید دوباره وضعیت مناسب مسیرها را محاسبه کنند.

مدت زمانی که شبکه برای رسیدن به وضعیت پایدار جدید نیاز دارد، Convergence Time نامیده می‌شود.

RSTP با مکانیزم‌های سریع‌تر می‌تواند این فرآیند را نسبت به STP کلاسیک سریع‌تر انجام دهد.

PortFast چیست؟

PortFast قابلیتی است که معمولاً روی پورت‌های متصل به End Device فعال می‌شود تا پورت سریع‌تر وارد وضعیت Forwarding شود.

برای مثال اگر یک کامپیوتر به Switch متصل باشد، منطقی نیست که پورت برای مدت طولانی منتظر فرآیندهای معمول STP بماند.

interface GigabitEthernet0/10 spanning-tree portfast
هشدار: PortFast نباید به‌صورت بی‌دلیل روی لینک‌های بین سوئیچ‌ها فعال شود. این قابلیت برای Edge/End Device Portها طراحی شده است.

BPDU Guard چیست؟

BPDU Guard یک مکانیزم حفاظتی است که معمولاً همراه PortFast در پورت‌های Edge استفاده می‌شود.

اگر پورتی که برای End Device در نظر گرفته شده BPDU دریافت کند، BPDU Guard می‌تواند پورت را برای جلوگیری از ایجاد مشکل در STP وارد وضعیت خطا کند.

interface GigabitEthernet0/10 spanning-tree portfast spanning-tree bpduguard enable

تنظیم Root Bridge در Cisco

در یک شبکه واقعی بهتر است Root Bridge را آگاهانه انتخاب کنیم و اجازه ندهیم انتخاب Root صرفاً بر اساس وضعیت تصادفی یا MAC Address انجام شود.

در برخی تجهیزات Cisco می‌توان از دستور زیر استفاده کرد:

spanning-tree vlan 10 root primary

این دستور برای VLAN مشخص، سوئیچ را برای نقش Root Primary تنظیم می‌کند.

بررسی وضعیت STP در Cisco

یکی از مهم‌ترین دستورات برای Troubleshooting:

show spanning-tree

برای مشاهده وضعیت STP یک VLAN مشخص:

show spanning-tree vlan 10

همچنین برای بررسی جزئیات وضعیت یک Interface می‌توان از:

show spanning-tree interface GigabitEthernet0/10 detail

یک سناریوی واقعی

شبکه سه سوئیچی

فرض کنید در یک شرکت سه سوئیچ داریم:

  • Core Switch
  • Distribution Switch
  • Access Switch

برای افزایش Redundancy، بین سوئیچ‌ها چند لینک ایجاد شده است. در صورت نبود STP، احتمال ایجاد Loop وجود دارد.

Core
↔
Distribution
↔
Access

STP می‌تواند یکی از مسیرهای Redundant را در وضعیت غیرForwarding نگه دارد. اگر مسیر اصلی قطع شود، مسیر جایگزین می‌تواند وارد مدار شود.

STP و Redundancy

نکته مهم این است که STP برای حذف کامل Redundancy طراحی نشده است. هدف آن جلوگیری از Loop در حالی است که مسیرهای جایگزین در توپولوژی وجود داشته باشند.

بنابراین اگر یک لینک فعال قطع شود، STP/RSTP می‌تواند مسیر جایگزین را فعال کند.

اشتباهات رایج در STP

۱. انتخاب نکردن Root Bridge

در شبکه‌های سازمانی بهتر است Root Bridge بر اساس طراحی شبکه مشخص شود، نه اینکه انتخاب آن کاملاً به صورت تصادفی انجام شود.

۲. فعال کردن PortFast روی لینک بین Switchها

این کار می‌تواند در شرایط نامناسب باعث ایجاد مشکلات جدی در توپولوژی Layer 2 شود.

۳. استفاده نکردن از BPDU Guard روی Edge Portها

در شبکه‌های سازمانی، ترکیب PortFast و BPDU Guard می‌تواند یک لایه حفاظتی مهم برای پورت‌های End Device فراهم کند.

۴. نادیده گرفتن تغییرات STP

تغییر Root، قطع لینک یا تغییر وضعیت پورت‌ها باید در زمان Troubleshooting بررسی شود.

STP یا RSTP؟

در شبکه‌های مدرن معمولاً RSTP انتخاب مناسب‌تری نسبت به STP کلاسیک است، زیرا Convergence سریع‌تری ارائه می‌دهد.

قاعده ساده:
STP = جلوگیری از Loop
RSTP = جلوگیری از Loop + Convergence سریع‌تر

چک‌لیست سریع Troubleshooting

  1. بررسی کنید Root Bridge کدام Switch است.
  2. وضعیت Root Portها و Designated Portها را بررسی کنید.
  3. Trunkها و VLANهای مجاز را بررسی کنید.
  4. وضعیت PortFast و BPDU Guard را بررسی کنید.
  5. تغییرات اخیر توپولوژی را بررسی کنید.
  6. لاگ‌های Switch را برای تغییرات STP بررسی کنید.

جمع‌بندی

STP یکی از پایه‌های مهم طراحی شبکه‌های Ethernet است. وقتی چند سوئیچ برای Redundancy به یکدیگر متصل می‌شوند، احتمال ایجاد Layer 2 Loop وجود دارد و STP وظیفه جلوگیری از این Loop را بر عهده دارد.

RSTP نسخه سریع‌تر و مدرن‌تر این مکانیزم است و در زمان تغییر توپولوژی می‌تواند سریع‌تر به وضعیت پایدار برسد.

در کنار STP/RSTP، قابلیت‌هایی مانند PortFast و BPDU Guard نیز برای محافظت بهتر از Edge Portها اهمیت زیادی دارند.

آنچه باید به خاطر بسپارید:

Root Bridge = نقطه مرجع STP
Root Port = بهترین مسیر به Root
Designated Port = مسیر Forwarding برای Segment
BPDU = پیام‌های کنترلی STP
RSTP = نسخه سریع‌تر STP
PortFast = ورود سریع Edge Port به Forwarding
BPDU Guard = محافظت از Edge Port در برابر BPDU
