مدل OSI چیست؟

مدل OSI یا Open Systems Interconnection یک مدل مفهومی برای توضیح نحوه ارتباط سیستم‌ها در شبکه است.

این مدل ارتباطات شبکه را به هفت لایه تقسیم می‌کند تا بتوانیم وظایف مختلف ارتباط شبکه را بهتر درک، طراحی و Troubleshoot کنیم.

نکته مهم:
OSI بیشتر یک مدل مرجع و آموزشی است. بسیاری از Protocolهای واقعی دقیقاً به شکل هفت لایه مستقل از هم پیاده‌سازی نشده‌اند؛ اما مدل OSI هنوز یکی از بهترین ابزارها برای فهم و عیب‌یابی شبکه است.

Layer 1 — Physical

لایه Physical پایین‌ترین لایه مدل OSI است. وظیفه آن انتقال سیگنال و بیت‌ها روی Media فیزیکی است.

مثال‌ها

  • کابل Ethernet
  • Fiber Optic
  • Connector
  • Radio Signal
  • Electrical Signal
  • Transceiver

Troubleshooting Layer 1

اگر سیستم اصلاً Link ندارد، ابتدا سراغ Layer 1 بروید.

PC │ ├── Cable │ ├── Patch Panel │ ├── Switch Port │ └── SFP / Fiber

Layer 2 — Data Link

Layer 2 مسئول ارتباط Data در سطح Local Network است. مفاهیمی مانند MAC Address و Ethernet Frame در این لایه اهمیت زیادی دارند.

تجهیزات و مفاهیم

  • Ethernet
  • MAC Address
  • Switch
  • VLAN
  • STP / RSTP
  • Frame
سؤال رایج:
Switch معمولاً در Layer 2 کار می‌کند، اما برخی Switchهای Multilayer می‌توانند قابلیت‌های Layer 3 نیز داشته باشند.

Layer 3 — Network

Layer 3 مربوط به آدرس‌دهی منطقی و انتقال Packet بین شبکه‌های مختلف است.

مهم‌ترین مفاهیم

  • IPv4
  • IPv6
  • Routing
  • Subnetting
  • Default Gateway
  • ICMP

مثال Routing

192.168.10.0/24 │ │ Router ▼ 192.168.20.0/24

وقتی مقصد در شبکه دیگری قرار دارد، Router برای انتقال Packet وارد عمل می‌شود.

Layer 4 — Transport

Transport Layer مسئول ارتباط End-to-End بین Applicationهاست. دو Protocol بسیار مهم این لایه TCP و UDP هستند.

ویژگی TCP UDP
Connection Connection-oriented Connectionless
Reliability دارد به‌صورت ذاتی ندارد
Overhead بیشتر کمتر
مثال HTTP/HTTPS, SSH DNS, DHCP, VoIP

Port Number

Portها کمک می‌کنند سیستم عامل بداند داده مربوط به کدام Service یا Application است.

IP Address + Port = Endpoint

Layer 5 — Session

Session Layer وظایف مربوط به ایجاد، مدیریت و پایان Sessionهای ارتباطی را در مدل OSI توضیح می‌دهد.

در دنیای واقعی، بسیاری از قابلیت‌هایی که به‌صورت مفهومی در Session Layer قرار می‌گیرند، ممکن است توسط Applicationها یا Protocolهای مختلف پیاده‌سازی شوند.

Layer 6 — Presentation

Presentation Layer مسئول نحوه نمایش و ساختار داده است.

  • Data Encoding
  • Data Translation
  • Compression
  • Encryption
مثال:
مفهوم Encryption و تبدیل Format داده را می‌توان برای درک آموزشی در Layer 6 قرار داد، هرچند در معماری‌های واقعی مرز این لایه با Application همیشه کاملاً جدا نیست.

Layer 7 — Application

Application Layer نزدیک‌ترین لایه OSI به نرم‌افزارهای کاربردی است و سرویس‌های شبکه‌ای مورد استفاده Applicationها را توصیف می‌کند.

نمونه Protocolها

  • HTTP / HTTPS
  • DNS
  • SMTP
  • FTP
  • SSH

Encapsulation چیست؟

زمانی که یک Application داده‌ای ارسال می‌کند، داده در مسیر عبور از Stack شبکه، اطلاعات کنترلی مربوط به لایه‌های مختلف را دریافت می‌کند.

Decapsulation چیست؟

در سمت مقصد، این فرآیند برعکس می‌شود. سیستم مقصد Headerهای مربوط به لایه‌های مختلف را پردازش می‌کند تا داده به Application برسد.

Bits ↓ Frame ↓ Packet ↓ Segment ↓ Data ↓ Application

OSI چگونه در Troubleshooting کمک می‌کند؟

یکی از بهترین کاربردهای OSI این است که هنگام بروز مشکل شبکه، Troubleshooting را مرحله‌به‌مرحله انجام دهیم.

سناریو: کاربر اینترنت ندارد

  1. آیا کابل یا Wi-Fi برقرار است؟ Layer 1
  2. آیا Switch Port و VLAN صحیح هستند؟ Layer 2
  3. آیا IP و Default Gateway صحیح هستند؟ Layer 3
  4. آیا Port موردنظر باز است؟ Layer 4
  5. آیا سرویس مقصد در دسترس است؟ Layer 7

مثال واقعی‌تر: سایت باز نمی‌شود

User │ ▼ Physical Link │ ▼ Switch / VLAN │ ▼ IP / Gateway │ ▼ Routing │ ▼ TCP 443 │ ▼ HTTPS │ ▼ Web Server

این مدل ذهنی کمک می‌کند به‌جای اینکه از همان ابتدا همه چیز را بررسی کنیم، مشکل را مرحله‌به‌مرحله محدود کنیم.

Ping در کدام Layer است؟

Ping از ICMP استفاده می‌کند و ICMP معمولاً در Network Layer یا Layer 3 دسته‌بندی می‌شود.

نکته بسیار مهم:
موفق بودن Ping به معنی سالم بودن تمام مسیر تا Application نیست. ممکن است Ping موفق باشد ولی TCP Port 443، سرویس Web یا Authentication مشکل داشته باشد.

مثال: Ping موفق است ولی سایت باز نمی‌شود

Ping ✓ │ ▼ Layer 3 OK TCP 443 ? │ ▼ Layer 4 HTTPS ? │ ▼ Layer 7

بنابراین در Troubleshooting نباید فقط به Ping اکتفا کرد.

OSI در شبکه‌های Enterprise

در شبکه‌های سازمانی، مشکلات ممکن است از هر لایه‌ای ایجاد شوند.

  • کابل معیوب → Layer 1
  • VLAN اشتباه → Layer 2
  • Route اشتباه → Layer 3
  • Firewall Port Block → Layer 4
  • DNS / Web / Authentication → Layer 7

چک‌لیست OSI برای Troubleshooting

  • Link و وضعیت Physical را بررسی کن.
  • Cable، SFP و Switch Port را بررسی کن.
  • VLAN و MAC Table را بررسی کن.
  • IP Address و Subnet Mask را بررسی کن.
  • Default Gateway را بررسی کن.
  • Routing Table را بررسی کن.
  • Firewall و Portهای موردنیاز را بررسی کن.
  • DNS و سرویس Application را بررسی کن.
  • در صورت نیاز Packet Capture انجام بده.

جمع‌بندی

مدل OSI فقط یک موضوع امتحانی برای Network+ نیست. اگر به‌درستی درک شود، تبدیل به یک ابزار ذهنی قدرتمند برای طراحی و Troubleshooting شبکه می‌شود.

وقتی بدانیم هر مشکل احتمالاً در کدام Layer قرار دارد، می‌توانیم دامنه جست‌وجوی مشکل را بسیار سریع‌تر محدود کنیم.
