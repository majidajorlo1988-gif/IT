SIP Register چیست؟

در شبکه‌های VoIP، تلفن یا Softphone باید خودش را به SIP Server معرفی کند تا سرور بداند این Extension در حال حاضر از چه IP و Portای قابل دسترسی است.

این فرآیند معمولاً با پیام SIP REGISTER انجام می‌شود.

IP Phone Extension 101
→
REGISTER SIP
→
SIP Server Issabel / Asterisk

پورت SIP چیست؟

در بسیاری از پیاده‌سازی‌ها SIP از UDP روی پورت 5060 استفاده می‌کند.

البته SIP می‌تواند روی Transportهای دیگر و Portهای متفاوت نیز پیکربندی شود؛ بنابراین نباید صرفاً بر اساس عدد 5060 نتیجه‌گیری کرد.

Component کاربرد نمونه
SIP Signaling REGISTER / INVITE / BYE
RTP انتقال صدا Audio Stream
UDP 5060 SIP Signaling در یک پیاده‌سازی رایج REGISTER

نکته مهم: SIP با RTP یکی نیست

یکی از اشتباهات رایج هنگام Troubleshooting این است که SIP و RTP را یک چیز در نظر بگیریم.

SIP برای Signaling استفاده می‌شود؛ یعنی مشخص می‌کند تماس چگونه ایجاد، مدیریت و پایان داده شود.

RTP معمولاً برای انتقال Media مانند صدای تماس استفاده می‌شود.

بنابراین:
ممکن است تلفن کاملاً Registered باشد، اما تماس بدون صدا باشد؛ در این حالت باید RTP، NAT و Firewall را بررسی کرد.

Torch؛ یکی از ابزارهای مفید MikroTik

Torch می‌تواند برای مشاهده Traffic عبوری از Interface بسیار مفید باشد.

IP Protocol Src. Address Dst. Address Port Packets Bytes

اگر انتظار دارید SIP Traffic از یک Interface عبور کند، می‌توانید بررسی کنید که آیا واقعاً Packetها در حال عبور هستند یا خیر.

آیا باز بودن Port به معنی سالم بودن SIP است؟

خیر.

این یکی از مهم‌ترین نکات Troubleshooting است.

Packet Flow ≠ Successful SIP Registration
ممکن است Packet به PBX برسد، اما Registration به دلیل Authentication، Configuration، State داخلی Asterisk، NAT یا سایر عوامل موفق نشود.

بررسی SIP با Packet Capture

اگر امکان Capture وجود داشته باشد، یکی از بهترین روش‌ها مشاهده مستقیم SIP Messageها است.

REGISTER ↓ 401 Unauthorized ↓ REGISTER + Authorization ↓ 200 OK

این Flow یک نمونه رایج از Authentication در SIP است. جزئیات دقیق بسته به پیاده‌سازی و تنظیمات متفاوت است.

معنی برخی Response Codeهای SIP

Code مفهوم کلی مسیر بررسی
200 OK درخواست موفق Registration معمولاً موفق شده است
401 Authentication Required Credential / Digest Authentication
403 Forbidden بررسی User / Policy / Authentication
404 Not Found بررسی Extension / Domain / Request
408 Request Timeout Network / Routing / Firewall

NAT و SIP

NAT یکی از معروف‌ترین منابع مشکل در VoIP است.

SIP در پیام‌های خود اطلاعاتی درباره Endpointها دارد و NAT می‌تواند باعث شود IP یا Port قابل استفاده با چیزی که واقعاً در شبکه وجود دارد متفاوت شود.

نکته:
قبل از اعمال تغییرات تصادفی روی NAT یا SIP ALG، ابتدا مسیر واقعی Packetها و نوع مشکل را مشخص کنید.

SIP ALG چیست؟

SIP ALG مکانیزمی است که برخی Routerها برای پردازش یا اصلاح SIP Traffic پشت NAT ارائه می‌کنند.

در بعضی محیط‌ها SIP ALG می‌تواند مفید باشد و در بعضی سناریوها باعث رفتارهای غیرمنتظره شود.

بنابراین فعال یا غیرفعال بودن آن باید بر اساس معماری و رفتار واقعی شبکه بررسی شود، نه صرفاً به‌عنوان یک دستورالعمل عمومی.

Issabel و Asterisk

Issabel یکی از Platformهایی است که می‌تواند برای راه‌اندازی سیستم تلفنی IP استفاده شود و از Asterisk به‌عنوان موتور اصلی Telephony بهره می‌برد.

اگر Packet به PBX می‌رسد اما تلفن Register نمی‌شود، باید وضعیت داخلی SIP Service و Configuration مربوط به Extension نیز بررسی شود.

Restart کردن سرویس چه زمانی مفید است؟

در محیط واقعی ممکن است سرویس Telephony یا یکی از Componentهای آن در وضعیت غیرعادی قرار گرفته باشد.

Restart کردن Service می‌تواند در بعضی شرایط مشکل را برطرف کند، اما نباید اولین یا تنها روش Troubleshooting باشد.

رویکرد حرفه‌ای:
ابتدا Evidence جمع کن → مشکل را Isolate کن → سپس در صورت نیاز Service را Restart کن → بعد نتیجه را دوباره Validate کن.

  • Default Gateway صحیح است.
  • VLAN صحیح است.

  • SIP Service سالم است.
  • NAT صحیح طراحی شده است.

جمع‌بندی

Troubleshooting در VoIP نباید بر اساس حدس انجام شود.

اگر تلفن Register نمی‌شود، باید مرحله‌به‌مرحله مشخص کنیم Packet از کجا حرکت می‌کند، در کجا متوقف می‌شود و آیا SIP Server واقعاً آن را پردازش می‌کند یا خیر.

در شبکه‌های چندسایته، ترکیب درست Routing، Tunnel، Firewall، NAT، SIP Configuration و PBX Monitoring اهمیت بسیار زیادی دارد.

قانون طلایی Troubleshooting:
اول Packet را پیدا کن، بعد مسیر را پیدا کن، سپس Service را بررسی کن، و در نهایت Configuration را تغییر بده.
