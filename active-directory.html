Active Directory چیست؟ راهنمای کامل AD، Domain و Group Policy

از Domain Controller و DNS تا User، Group، OU و Group Policy؛ یک راهنمای عملی برای درک و مدیریت Active Directory در شبکه‌های سازمانی.

Intermediate / Advanced حدود 16 دقیقه مطالعه Windows Server Active Directory Security

Active Directory چیست؟

Active Directory یا به اختصار AD، سرویس دایرکتوری مایکروسافت برای مدیریت متمرکز هویت، کاربران، کامپیوترها، منابع و Policyهای یک شبکه سازمانی است.

در یک سازمان، به‌جای اینکه روی تک‌تک کامپیوترها User و Permission را به‌صورت جداگانه مدیریت کنیم، می‌توانیم مدیریت هویت و دسترسی را از طریق Domain مرکزی انجام دهیم.

مفهوم ساده:
Active Directory را می‌توان مانند یک سیستم مرکزی برای مدیریت کاربران، کامپیوترها، دسترسی‌ها و Policyهای شبکه تصور کرد.

چرا سازمان‌ها از Active Directory استفاده می‌کنند؟

فرض کنید یک شرکت 100 کاربر و 120 کامپیوتر دارد. اگر همه چیز Local باشد، مدیریت Userها، Passwordها، Permissionها و تنظیمات امنیتی بسیار دشوار می‌شود.

Domain باعث می‌شود بسیاری از این وظایف به شکل متمرکز مدیریت شوند.

01
Centralized Management مدیریت متمرکز کاربران و کامپیوترها
02
Authentication احراز هویت متمرکز
03
Group Policy اعمال Policy روی سیستم‌ها
04
Access Control کنترل دسترسی به منابع

Domain چیست؟

Domain یک محدوده مدیریتی و امنیتی در شبکه است که منابع و هویت‌ها در آن تحت مدیریت Active Directory قرار می‌گیرند.

برای مثال:

corp.example.local

یا در محیط‌های مدرن‌تر، نام‌گذاری Domain می‌تواند بر اساس ساختار DNS سازمان انجام شود.

Domain Controller چیست؟

سروری که سرویس Active Directory Domain Services یا AD DS روی آن نصب و پیکربندی شده باشد و نقش Domain Controller را ایفا کند، وظایف اصلی مربوط به Domain را انجام می‌دهد.

User Credentials
→
Domain Controller Authentication
→
Domain Resources Access

آیا فقط یک Domain Controller داشته باشیم؟

از نظر فنی می‌توان یک Domain Controller داشت، اما در بسیاری از محیط‌های سازمانی، داشتن بیش از یک DC برای افزایش Availability و تحمل خرابی اهمیت زیادی دارد.

نکته مهم:
Domain Controller دوم فقط برای "Backup" نیست؛ Replication بین DCها و Availability سرویس Directory از دلایل مهم استفاده از چند DC است.

Active Directory و DNS

DNS یکی از مهم‌ترین وابستگی‌های Active Directory است.

بسیاری از سرویس‌های AD برای پیدا کردن Domain Controller و سرویس‌های مربوط به Domain از DNS استفاده می‌کنند.

قانون مهم:
اگر DNS در Domain به‌درستی طراحی نشده باشد، مشکلاتی مانند Login، Domain Join، Group Policy و پیدا کردن DC می‌توانند ظاهر شوند.

ساختار کلی یک Domain

Active Directory Domain │ ├── Users │ ├── Computers │ ├── Groups │ ├── Organizational Units │ ├── Group Policy Objects │ └── Domain Controllers

User چیست؟

User Account برای شناسایی و احراز هویت یک کاربر در Domain استفاده می‌شود.

یک User می‌تواند اطلاعاتی مانند Username، Password، Group Membership و Permissionهای مرتبط داشته باشد.

مثال

Username: majid Domain: CORP Logon: CORP\majid

Computer Account چیست؟

زمانی که یک کامپیوتر را به Domain Join می‌کنیم، یک Computer Account در Active Directory برای آن سیستم ایجاد می‌شود.

Windows PC
→
Domain Join
→
Computer Account

Domain Join چیست؟

Domain Join فرآیندی است که طی آن یک سیستم Windows به Domain سازمان متصل می‌شود.

بعد از Join، سیستم می‌تواند از امکاناتی مانند Domain Authentication و Group Policy استفاده کند.

قبل از Domain Join بررسی کنید:
IP Address، DNS، Default Gateway، ساعت سیستم و دسترسی به Domain Controller صحیح باشند.

Group چیست؟

Group برای دسته‌بندی Userها یا Computerها و ساده‌تر کردن مدیریت Permission استفاده می‌شود.

به‌جای اینکه Permission یک Share را برای 50 کاربر به‌صورت جداگانه تنظیم کنیم، می‌توانیم Userها را داخل یک Group قرار دهیم و Permission را به Group بدهیم.

مثال File Server

Users │ ├── Ali ├── Sara ├── Reza └── Majid │ ▼ FileServer-Users │ ▼ \\FileServer\Shared

OU چیست؟

Organizational Unit یا OU برای سازمان‌دهی Objectهای Active Directory استفاده می‌شود.

OUها نقش بسیار مهمی در Delegation و اعمال Group Policy دارند.

CORP │ ├── OU=Users │ ├── OU=Computers │ ├── OU=Servers │ ├── OU=IT │ └── OU=Branches

چرا OU مهم است؟

فرض کنید سازمان چند شعبه دارد. می‌توانیم ساختار منطقی برای مدیریت سیستم‌ها ایجاد کنیم.

نمونه ساختار سازمانی

CORP │ ├── HQ │ ├── Users │ └── Computers │ ├── Branch-01 │ ├── Users │ └── Computers │ ├── Branch-02 │ ├── Users │ └── Computers │ └── Servers

Group Policy چیست؟

Group Policy یا GPO یکی از قدرتمندترین قابلیت‌های Active Directory برای اعمال تنظیمات متمرکز روی Userها و Computerها است.

با GPO می‌توان بسیاری از تنظیمات امنیتی و مدیریتی را بدون مراجعه به تک‌تک سیستم‌ها اعمال کرد.

نمونه کاربردهای GPO

  • Password Policy
  • Account Lockout Policy
  • Windows Firewall
  • محدود کردن دسترسی کاربران
  • تنظیمات Desktop
  • Drive Mapping
  • Software Deployment
  • Security Configuration
  • تنظیمات Windows Update

GPO چگونه اعمال می‌شود؟

Domain
→
Site
→
Domain / OU
→
User / Computer

محل قرار گرفتن Objectها و Scope مربوط به Policy اهمیت زیادی دارد. بنابراین طراحی صحیح OU Structure مستقیماً روی مدیریت GPO تأثیر می‌گذارد.

Authentication در Active Directory

وقتی کاربر با Account دامینی Login می‌کند، سیستم باید هویت او را در Domain بررسی کند.

در محیط‌های Active Directory مدرن، Kerberos یکی از پروتکل‌های اصلی Authentication است.

User │ │ Credentials ▼ Domain Controller │ │ Authentication ▼ Kerberos / Domain Services │ ▼ Access Granted

Authentication با Authorization فرق دارد

مفهوم سؤال مثال
Authentication تو چه کسی هستی؟ Login با User Account
Authorization به چه چیزی دسترسی داری؟ دسترسی به Folder

Active Directory و File Server

یکی از رایج‌ترین کاربردهای AD، مدیریت دسترسی کاربران به File Server است.

مدل پیشنهادی

User │ ▼ Security Group │ ▼ NTFS Permission │ ▼ Share │ ▼ File Server

در طراحی Permission بهتر است به‌جای اختصاص مستقیم Permission به Userها، از Groupها برای مدیریت دسترسی استفاده شود.

Domain Admin چیست؟

Domain Admin یک سطح دسترسی بسیار قدرتمند در Domain است و معمولاً نباید برای فعالیت‌های روزمره کاربران استفاده شود.

Security Principle:
از حساب‌های دارای Privilege بالا فقط زمانی استفاده کنید که واقعاً به آن سطح دسترسی نیاز دارید.

Least Privilege در Active Directory

اصل Least Privilege می‌گوید هر User یا Service باید فقط به اندازه‌ای که برای انجام وظیفه نیاز دارد Permission داشته باشد.

  • کاربران عادی Domain Admin نباشند.
  • Service Accountها دسترسی بیش از نیاز نداشته باشند.
  • Administrator Accountها برای کارهای روزمره استفاده نشوند.
  • Delegation برای وظایف مشخص استفاده شود.

Time Synchronization چرا مهم است؟

در محیط‌های Domain، هماهنگ بودن ساعت سیستم‌ها اهمیت زیادی دارد.

اختلاف زمانی قابل توجه می‌تواند باعث بروز مشکلات Authentication، مخصوصاً در سناریوهای مبتنی بر Kerberos شود.

بررسی کنید:
Domain Controllerها، Serverها و Clientها Time Source مناسب و هماهنگی زمانی صحیح داشته باشند.

Replication بین Domain Controllerها

وقتی چند Domain Controller داریم، تغییرات Active Directory باید بین DCها Replicate شوند.

DC-01 Site A
⇄
DC-02 Site A
⇄
DC-03 Site B

در محیط‌های چندسایته، طراحی Site و ارتباط بین Domain Controllerها اهمیت زیادی دارد.

Active Directory Site چیست؟

Site در Active Directory معمولاً برای نمایش ساختار فیزیکی شبکه و Subnetها استفاده می‌شود.

Siteها می‌توانند به Active Directory کمک کنند تا Replication و انتخاب سرویس‌های مناسب را با توجه به توپولوژی شبکه مدیریت کند.

Backup از Active Directory

Active Directory نیز مانند هر سرویس حیاتی دیگری نیاز به Backup و Recovery Plan دارد.

داشتن یک Domain Controller دوم به معنی داشتن Backup کامل از Active Directory نیست.

نکته:
Redundancy و Backup دو مفهوم متفاوت هستند. Replication به معنی داشتن یک Backup مستقل برای Recovery نیست.

اگر Domain Login مشکل داشت، از کجا شروع کنیم؟

  1. IP Address را بررسی کنید.
  2. DNS Client را بررسی کنید.
  3. ارتباط با Domain Controller را بررسی کنید.
  4. وضعیت Time Synchronization را بررسی کنید.
  5. وضعیت Computer Account را بررسی کنید.
  6. Event Viewer را بررسی کنید.
  7. وضعیت سرویس‌های Domain Controller را بررسی کنید.
  8. Replication را در صورت وجود چند DC بررسی کنید.

چند دستور مفید برای Troubleshooting

ipconfig /all nslookup domain.local whoami gpupdate /force gpresult /r dcdiag repadmin /replsummary

خروجی هر دستور باید در Context همان مشکل تحلیل شود؛ اجرای دستور بدون درک نتیجه آن به‌تنهایی Troubleshooting محسوب نمی‌شود.

GPUpdate و GPResult

برای بررسی Group Policy روی Clientها، دو ابزار بسیار کاربردی gpupdate و gpresult هستند.

gpupdate /force gpresult /r

دستور اول تلاش می‌کند Policyها را مجدداً اعمال کند و دستور دوم اطلاعاتی درباره Policyهای اعمال‌شده ارائه می‌دهد.

اشتباهات رایج در Active Directory

  • استفاده نادرست از DNS.
  • قرار دادن تمام Userها و Computerها در یک OU بدون طراحی مناسب.
  • استفاده روزمره از Domain Admin.
  • نداشتن Backup و Recovery Plan.
  • نداشتن Domain Controller اضافی در محیط‌های حساس.
  • نادیده گرفتن Time Synchronization.
  • اعمال GPO بدون تست روی OU آزمایشی.
  • دادن Permission مستقیم به تعداد زیادی User.
  • نادیده گرفتن Event Viewer و Logها.

چک‌لیست مدیریت حرفه‌ای Active Directory

  • DNS به‌درستی طراحی شده باشد.
  • حداقل یک Domain Controller سالم و قابل دسترس وجود داشته باشد.
  • برای محیط‌های حساس Redundancy مناسب در نظر گرفته شود.
  • Backup و Recovery Plan مستند باشد.
  • Userها و Computerها در OUهای منطقی قرار گرفته باشند.
  • Groupها بر اساس نیاز سازمان طراحی شده باشند.
  • Permissionها بر اساس Least Privilege باشند.
  • Domain Admin فقط برای فعالیت‌های مدیریتی استفاده شود.
  • GPOها قبل از Production تست شوند.
  • Time Synchronization بررسی شود.
  • Replication بین DCها Monitoring شود.
  • Event Logها و Alertها بررسی شوند.

جمع‌بندی

Active Directory یکی از پایه‌های اصلی بسیاری از زیرساخت‌های Windows-based سازمانی است.

طراحی صحیح AD فقط نصب Domain Controller نیست؛ بلکه ترکیبی از DNS، Authentication، OU Structure، Group Policy، Security، Replication، Backup و Monitoring است.

هرچه سازمان بزرگ‌تر شود، اهمیت طراحی منطقی و امن Active Directory نیز بیشتر می‌شود.
